# CarBuy MVP 9.9–9.15 implementation status

The supplied PRD's MVP section ends at **9.15**. There are no MVP subparts 9.16–9.25 in that document; sections 10–25 cover later product, launch and expansion planning. The statuses below describe this repository as shipped, not a claim that a real marketplace is already operating.

| PRD IDs | Current implementation | Status before public launch |
| --- | --- | --- |
| TNS-01–03 | Private listings enter review; configurable low-risk publish gate defaults off. Risk assessment includes account age, chassis duplication, exact/perceptual photo duplication, low price, text/OCR contact clues and posting velocity. | **Partial:** moderation SLA, OCR provider, price-comparable data and tuned production rules need operations/integration. |
| TNS-04–08 | Listing and dealer services support moderator decisions, change requests, rejection, papers match checks, dealer verification, reports and audit records. Demo moderation queue exposes risk signals. | **Partial:** no unified production admin auth, phone/device bans, complete content enforcement or real trade-licence checks. |
| TNS-09–10 | Safety, auction, scam and listing-rule guidance in Bangla/English; report/block flows exist in messaging demo. | **Partial:** Android UGC compliance cannot be tested until an app exists; legal/content policy needs review. |
| PAY-01–08 | `platform` has a gateway adapter, BDT price configuration, settlement verification, coupons, boosts, dealer credit packs, auction-sheet queue, receipts/VAT fields and refund flow. Existing listing/dealer demos simulate private listing fees and credits. | **Partial:** no merchant account, gateway adapter implementation, webhook signature handling, durable order storage, live VAT configuration or end-to-end entitlement integration. Android payment policy awaits app design. The payment demo must never accept real payments. |
| APP-01–06 | Web flows provide reusable search, detail, chat, saved cars and sell prototypes. | **Not built:** no Android app, FCM, app links, offline mode, performance certification or Play Store release. A Play Console account is required for release. |
| SEO-01–05 | Black storefront is server-rendered. Search service has bilingual guidance/programmatic routes, canonical/hreflang/breadcrumb/sitemap logic and listing-count thresholds. | **Partial:** black storefront lacks full bilingual programmatic page integration and measured Core Web Vitals. Sample-data preview is intentionally `noindex`; draft legal pages need counsel review. |
| NOT-01–03 and Appendix B | Bilingual notification templates, channel matrix, per-type preferences, deduplication and local in-app/outbox services in `platform`. | **Partial:** no FCM, email or Bangladesh SMS providers; no durable delivery queue or integrated event triggers. Sign-in SMS belongs to the future auth service. |
| ADM-01–09 and Appendix A | Listing/dealer admin operations and auction-sheet queue exist as service modules; actions are audited in some modules. | **Partial:** no unified role-protected admin console, cross-module search, full papers queue, central audit log or KPI dashboard. Demo admin endpoints are localhost-only and must not be exposed publicly. |
| ANL-01–03 | Consent-gated event schema, safe property whitelist, deletion on consent withdrawal and UTM/referrer/Play-referrer parsing in `platform`. | **Partial:** no web/app event instrumentation, consent UI, durable analytics store or dashboards. |

The black storefront connects to the sample inventory on port 4175. Interactive detail/chat, saved cars, seller studio and dealer portal currently open their respective local demo modules; they are not all yet native black-theme screens. This is visible in the UI and needs integration before a cohesive public launch.

Public launch also needs hosted backend/database/storage, real phone authentication and abuse protection, a Bangladesh payment merchant account, notification providers, a domain and operational review staff. GitHub hosts the source code; GitHub Pages is static hosting and is not a suitable production host for the transactional marketplace.
